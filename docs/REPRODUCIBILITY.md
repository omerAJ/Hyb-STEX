# Reproducing the final Hyb-STEX results

This document describes the submission configuration, not the exploratory
classifier-gated, dual-residual, threshold-sensitivity, or capacity-control
ablations retained under `scripts/`.

## Final model

The public Hyb-STEX model is `D_frozen_residual_event_weighted`:

- base: STE-Base prediction path trained with ordinary MAE;
- residual: one always-on residual head;
- schedule: freeze the selected base checkpoint, then train only the residual;
- event objective: ordinary MAE plus `0.25 ×` MAE on p90 events;
- threshold: 90th percentile of training targets, fitted separately for each
  forecast horizon, node, and flow direction;
- valid observations: target flow strictly greater than 5;
- final evaluation phase: `pred_2`;
- random seeds: 1, 2, and 3.

The event label is derived entirely from training targets. Validation examples
are used for checkpoint selection; test examples are used only for final
metrics and figures.

## Prepare the data

Place the original ST-SSL splits under `external/ST-SSL_Dataset`, then run:

```bash
python scripts/create_ev_labels.py \
  --data-dir external/ST-SSL_Dataset \
  --output-dir preprocessed_data \
  --percentile 90
```

The command writes copies rather than mutating the source files. Each generated
`train.npz`, `val.npz`, and `test.npz` contains a verified `evs_90` tensor.

## Inspect the run

The dry run prints the two resumable phase commands and performs no training:

```bash
python scripts/run_hybstex.py --dry-run
```

## Smoke test

```bash
python scripts/run_hybstex.py \
  --datasets NYCTaxi \
  --seeds 1 \
  --device cpu \
  --smoke-test \
  --output-dir results/smoke
```

The smoke test verifies wiring only. Its metrics are not paper results.

## Full four-dataset run

```bash
python scripts/run_hybstex.py \
  --datasets NYCBike1 NYCBike2 NYCTaxi BJTaxi \
  --seeds 1 2 3 \
  --device cuda \
  --data-dir preprocessed_data \
  --output-dir results/hybstex
```

The same run is available through the main entry point:

```bash
python main.py --submission-run --device cuda
```

The runner is resumable. It records each completed seed and validates its
manifest before reuse. Do not pass `--restart` for ordinary continuation.

## Result files

The two underlying stages retain their complete metrics and manifests under
`base/` and `final/`. For paper tables, use the filtered files at the output
root:

- `per_seed_metrics.csv`: one row per dataset, seed, and flow aggregation;
- `summary_metrics.csv`: mean and standard deviation across seeds;
- `run_info.json`: final model name and protocol settings.

The canonical summary contains only `D_frozen_residual_event_weighted`. Lower
MAE and EEE are better. `event_signed_error` is useful for diagnosing systematic
high-flow underprediction but is not an absolute-error metric.

## Evaluate a subset

Dataset and seed filters do not change the model definition:

```bash
python scripts/run_hybstex.py \
  --datasets NYCBike1 NYCTaxi \
  --seeds 1 2 3 \
  --device cuda \
  --output-dir results/bike1_nyctaxi
```

## Publication figures

The qualitative plotting scripts perform inference from saved checkpoints;
they do not train models. The final full-page figure is generated by:

```bash
python scripts/plot_figure3_eight_panel.py
```

It contains, for each dataset, the selected high-flow test window and the
full-test KDE for the identical node and flow direction. All KDE curves in a
panel share one nonnegative evaluation grid. Figure scripts expect the
paper-run checkpoint/manifests described in their module constants; adjust
those paths only when moving an archived paper run.

## Protocol safeguards

The regression tests cover:

- training-only p90 threshold fitting;
- strict valid/event masks;
- corrected MAE and EEE aggregation;
- evaluation-phase selection and prediction capture;
- CPU/CUDA device resolution;
- corrected-runner manifests and resume behavior.

Run them with:

```bash
pytest -q
```
